# 业务说明

## 1. 这个系统解决什么问题

在晶圆制造/封装测试中，良率损失通常分两类：

1. **系统性损失**：某台设备、某道工艺、某个 recipe 持续偏移，导致整批晶圆良率下降；
2. **偶发性损失**：短时间的参数漂移、颗粒污染、设备异常，造成局部失效。

两类问题都要求工程团队**尽早发现异常批次**，而不是等终测（final test）才看到结果。越晚发现，越多的晶圆已经流到下游，返工与报废成本越高。

本系统把"发现异常"拆成三个可执行动作：

| 动作 | 系统能力 | 业务价值 |
| --- | --- | --- |
| 看趋势 | 日良率 + 预测风险均值 | 判断是偶发还是系统性 |
| 查异常 | 高风险晶圆列表 + 风险分档 | 优先复判最可疑的批次 |
| 找原因 | 单晶圆参数归因（Top 10） | 把"这片有问题"变成"哪个参数有问题" |

## 2. 为什么用"固定误报率"而不是"准确率"

产线不可能无限复判。假设每天产出 1,000 片，如果模型报警 300 片，工程团队根本处理不过来，模型会被弃用。因此业务上更合理的问法是：

> 在每天最多复判 N 片（即固定误报预算）的前提下，能抓住多少真正会失效的晶圆？

本项目把预算固定为 **测试期 5% FPR**，在这个约束下报告召回率。这样指标可以直接映射到"每天多复判多少片、能减少多少 escape"。

## 3. 指标口径

| 指标 | 含义 | 为什么重要 |
| --- | --- | --- |
| AUC | 随机取一片失效和一片合格，模型给失效更高分的概率 | 衡量排序能力，与阈值无关 |
| PR-AUC | Precision-Recall 曲线下面积 | 正类只占 6.6% 时比 AUC 更敏感 |
| Recall @ 5% FPR | 误报不超过 5% 时的召回 | 直接对应复判产能 |
| 预警数 / 实际失效 | 14 条预警覆盖 9 片失效中的 2 片 | 一眼看懂运行点 |
| Brier | 概率预测的均方误差 | 概率是否可用于排序之外的成本计算 |

**不要看 Accuracy**：全判合格就有 93.4%，这个数字没有业务含义。

## 4. 看板怎么读

打开 `dashboard/index.html`（离线可用，无需服务）。

1. **顶部 KPI**：测试期 AUC、PR-AUC、Recall@5%FPR、预警数、缺陷 Macro-F1、质量门禁状态。先看质量门禁，PASS 才继续看模型。
2. **良率趋势**：绿线是实际日良率，黄线是测试期模型平均风险。黄线抬升而绿线未同步下降，说明模型在提示"未来可能变差"。
3. **测试期风险分布**：如果模型有效，高风险区间应该集中更多真实失效；当前样本少，分布只能作为参考。
4. **高风险晶圆预警**：按预测概率排序。点击任意行，右侧归因图会切换到该片，显示哪些参数把它推向失效。
5. **关键参数漂移**：日均值相对训练基线的 z-score，±3σ 为控制线。用于回答"是不是某个参数整体漂了"。
6. **缺陷类型分布 / 代表性晶圆图 / 混淆矩阵**：来自 WM-811K，展示缺陷图谱分类能力与易混淆类别（Scratch、Loc）。
7. **业务价值测算**：基于配置中的假设做敏感性测算，不是财务口径的已实现收益。

## 5. 业务价值怎么算（以及为什么不能直接信）

当前测试期结果：14 条预警，命中 2 片失效，12 次误报。

情景假设（写在 `configs/config.yaml`，可改）：

- 单片晶圆价值：3,000 元；
- 漏检流出成本 = 单片价值 × 10 = 30,000 元；
- 每次误报复判成本：300 元。

净价值 = 2 × 30,000 − 12 × 300 = **+56,400 元**（测试期 235 片）。

必须说明：

- 这是**情景测算**，不是已实现收益；
- 10 倍 escape 系数是行业经验假设，不同产品差异很大；
- 没有计入模型维护、数据平台、工程师时间等成本；
- 测试期只有 9 片失效，结论的统计置信度很低。

面试时正确的说法是："这个模型在测试期按 5% 误报预算能抓住 22% 的失效，按情景假设净收益为正；但样本量不足以支撑上线决策，下一步需要更长时间的数据做在线验证。"

## 6. 如果真上产线，还需要什么

| 缺口 | 需要的数据/能力 |
| --- | --- |
| 批次维度 | lot_id、wafer_id 与 lot 的映射、批次时间 |
| 设备根因 | 设备 commonality、chamber、recipe 版本 |
| 更早预警 | 工序中间测量点（inline metrology），而不是终测后 |
| 闭环 | 复判结果回写、模型在线监控、漂移告警、定期重训 |
| 成本 | 真实 escape 成本、复判工时、报废/返工规则 |

本项目把这些缺口显式写出来，而不是假装一个 0.6 AUC 的模型可以直接上产线。这是数据工程岗位应有的判断。
