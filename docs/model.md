# 模型说明

## 1. 问题定义

良率预测被定义为一个**代价敏感的二分类**：给定一片晶圆在加工过程中采集的 590 个传感器值，输出失效概率，并按固定误报预算给出预警。

不优化 Accuracy：失效率只有 6.64%，全判合格就有 93.4% 的准确率，但会漏掉全部失效。制造业更关心：

- **Recall @ 固定 FPR**：在可接受的误报量下能抓到多少失效；
- **PR-AUC**：正类极少时比 ROC-AUC 更敏感；
- **业务净值**：避免的 escape 成本 − 误报复判成本。

## 2. 时间切分与回测

### 为什么不能随机切分

SECOM 覆盖 2008-07 至 2008-10 约三个月。随机切分会让模型在训练时"看到未来"：同一批设备状态、同一段工艺漂移会同时出现在训练和测试里，AUC 会被显著高估。真实部署是**用过去预测未来**，因此本项目：

- 按 `measurement_ts` 排序后 70/15/15 切分；
- 训练期截止 `2008-09-26 03:12`，测试期从 `2008-10-05 20:12` 开始；
- 质量门禁断言 `train_max < test_min`。

### 5 折滚动起点（rolling-origin）

单次 15% 留出只有 9 片失效，AUC 的 95% CI 宽达 0.37–0.82，无法可靠比较模型。因此在开发期（train+valid）内做扩展窗口回测：

- 初始训练窗口占开发期 55%，之后 5 个连续时间块依次作为测试块；
- 每折的阈值取该折训练窗口尾部 15% 的 5% FPR 分位；
- 模型选择依据：5 折平均 AUC，PR-AUC 作为并列时的次级依据。

结果：

| 模型 | 回测 AUC | 回测 PR-AUC | 回测 Recall@5%FPR |
| --- | --- | --- | --- |
| LightGBM | 0.585 ± 0.150 | 0.136 ± 0.169 | 0.0% |
| 逻辑回归 | 0.572 ± 0.141 | 0.076 ± 0.050 | 5.0% |

两者在统计上几乎不可区分，LightGBM 因 AUC 与 PR-AUC 略高被选中。**回测 Recall 为 0 是真实结果**：每折只有 7–14 片失效，阈值稍微上移就会清空召回，说明当前样本量下运行点极不稳定。

### 阈值冻结

1. 用选中的模型在 5 折中得到的 **out-of-fold 分数**汇总；
2. 在全部 OOF 负样本上取 5% FPR 对应的分位点，得到阈值 **0.1416**；
3. 该阈值冻结，之后只对测试期使用一次，避免在测试集上调参。

### 最终训练与测试

选定模型后在 train+valid（1,332 片）上重训，测试期（235 片）只评估一次：

| 指标 | 数值 |
| --- | --- |
| AUC | 0.601（95% CI 0.375–0.817，bootstrap 1000 次） |
| PR-AUC | 0.116（随机基线 0.038） |
| Recall @ 5% FPR | 22.2%（9 片失效中命中 2 片） |
| Precision | 14.3%（14 条预警） |
| 实际 FPR | 5.3% |
| Brier | 0.0398 |

测试期只有 9 个正例，任何单点指标的置信区间都很宽。这个结果**足以证明评估框架正确，不足以证明模型可上线**。

## 3. 特征工程

- **常量列**：116 个传感器只有 1 个取值，剔除；
- **高缺失**：32 个传感器缺失率 > 40%（最高 91.2%），剔除；
- **剩余 436 个传感器** + 4 个衍生特征（`z_mean`、`z_std`、`z_max_abs`、`abnormal_cnt`），共 440 维；
- **填充**：用训练期中位数（不是全局中位数，避免泄漏）；
- **异常值**：按训练期均值/标准差做 ±6σ 缩尾，并单独记录 `outlier_cnt`，不直接删除（异常本身可能是信号）；
- **衍生特征**：晶圆级标准化参数分布，刻画"整体偏移"与"波动放大"。

## 4. 归因

- LightGBM：原生 `pred_contrib=True`，即 TreeSHAP，输出每个特征对 log-odds 的加性贡献；
- 逻辑回归：`coef × z-score`，同样是精确加性贡献；
- 全局重要性：LightGBM gain + 测试期置换重要性（permutation importance，AUC 口径）+ 平均绝对归因，三种口径交叉验证。

当前 Top 驱动：`S060`、`S034`、`S461`、`S022`、`S091`。它们只说明"模型依赖这些信号"，**不等于工艺根因**；根因还需要设备 commonality、recipe 版本与工程师验证。

## 5. 缺陷分类（WM-811K）

- 输入：26 维派生特征（行列数、die 数、失效 die 数、良率、缺陷密度、中心/中间/边缘比例、四象限不均衡、质心/扩散、径向统计、聚类数等）；
- 切分：沿用官方 Training/Test（54,355 / 118,595），不重新随机切分；
- 类别不平衡：`none` 占 93.3%，LightGBM 使用类别权重，逻辑回归 `class_weight=balanced`；
- 选型：LightGBM（Macro-F1 0.602）优于逻辑回归（0.499）。

| 类别 | Precision | Recall | F1 | 测试样本 |
| --- | --- | --- | --- | --- |
| none | 0.988 | 0.963 | 0.976 | 110,701 |
| Center | 0.422 | 0.739 | 0.537 | 832 |
| Donut | 0.515 | 0.459 | 0.486 | 146 |
| Edge-Loc | 0.524 | 0.707 | 0.602 | 2,772 |
| Edge-Ring | 0.689 | 0.569 | 0.623 | 1,126 |
| Loc | 0.427 | 0.428 | 0.427 | 1,973 |
| Random | 0.832 | 0.673 | 0.744 | 257 |
| Scratch | 0.058 | 0.176 | 0.087 | 693 |
| Near-full | 0.895 | 0.989 | 0.940 | 95 |

`Scratch` 最差：线性划痕在 26 维统计特征里与 `Loc`/`Random` 高度混淆。这正说明**图谱任务不能只靠几何统计特征**，下一步应上原图 CNN。

## 6. 失败模式与改进方向

1. **样本量与方差**：1,567 片、104 个失效，时间外推下任何模型都不稳定。需要更长的时间跨度与更多失效样本。
2. **概念漂移**：SECOM 三个月内工艺状态变化明显；应引入在线监控与定期重训，而不是一次训练长期使用。
3. **缺失机制**：传感器缺失往往与产品/工艺路线相关，当前用中位数填充会丢失信息；可加入缺失指示变量。
4. **无批次/设备维度**：无法做 commonality 分析，归因只能到参数级。
5. **缺陷模型**：派生特征不是原图；应使用 CNN/ViT，并引入 die 级坐标与缺陷掩码。

## 7. 复现

```bash
python -m src.cli all     # 全流程
python -m src.cli train   # 只重训良率模型（需要已建数仓）
```

所有随机种子固定在 `configs/config.yaml`；模型、指标、归因、预测明细分别写入 `artifacts/`。
