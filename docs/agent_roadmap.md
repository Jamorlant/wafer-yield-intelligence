# Agent 路线：L0 → L3

> 结论先说：当前交付只做到 **L2 的规则版建议**，没有接入真实 LLM，也没有任何自动执行。
> L3 是产品愿景页，用于对齐下一阶段，不代表已实现能力。

## 1. 四级能力与当前状态

| 级别 | 能力 | 输入 | 输出 | 状态 |
| --- | --- | --- | --- | --- |
| **L0** | 报表自动化 | MES 批次/工序/参数 | 日良率、工序良率、损失构成 | ✅ 已实现 |
| **L1** | 规则预警 | 小时参数序列 | SPC 告警 + 可疑批次 | ✅ 已实现 |
| **L2** | 归因与建议 | 告警 + 回溯窗口 | 参数级证据 + 建议动作 + 责任人 | 🟡 规则版已实现，LLM 未接入 |
| **L3** | 自主闭环 | 建议 + 人工确认结果 | 工单、复判、阈值回写 | ⬜ 愿景，未实现 |

### L0 报表自动化（已实现）

- 分层数仓 ODS → DWD → DWS → ADS，每层有行数与口径校验；
- 固定随机种子，`digest` 可复现；
- 静态单文件看板，离线可开，不依赖服务。

### L1 规则预警（已实现）

- 小时均值 + 冻结基线（前 60 天）的 3σ 控制图；
- `R1_3SIGMA`（连续 3 点越界）与 `R2_SEVEN_POINT`（连续 7 点同侧且偏移 ≥ 2σ）；
- 每条告警落到「线 × 工序 × 设备 × 参数」，并回溯 8 小时的可疑批次。

### L2 归因与建议（规则版已实现）

- 证据模板由 `src/warehouse/mes.py::_alert_evidence` 生成：
  参数名、基线、控制限、z 值、偏移描述；
- 建议动作由 `ACTION_BY_PROCESS` 按工序给出（如「贴片：复核温控与点胶」），
  **不是 LLM 生成**；
- 责任人来自工序配置 `owner`，路由到班组长 / 工艺 / 设备 / 测试。

**如果接入 LLM，边界是**：LLM 只做「把结构化证据改写成给工程师看的自然语言」和
「检索历史相似工单」，不参与是否告警、是否停机的判断。判断仍由 SPC 规则给出，
保证可复现、可审计。

### L3 自主闭环（愿景，未实现）

- 建议 → 工单 → 复判结果 → 回写；
- 用复判结果评估建议采纳率与命中率，反哺规则阈值；
- 任何动设备的动作都需要人确认，Agent 不直接写 MES/EAP。

## 2. 护栏

| 护栏 | 做法 |
| --- | --- |
| 只读 | Agent 不写 MES/EAP，不下发配方，不调机台参数 |
| 可解释 | 每条建议必须挂到一条告警 + 一个参数 + 一个回溯窗口 |
| 可回滚 | 建议以工单形式给人，人确认后才执行 |
| 可评估 | 采纳率、复判命中率、误报率持续回写 |
| 数据合规 | 真实数据不出厂，模型与日志留在内网 |
| 合成标注 | 演示数据在看板首屏明确标注，不伪装成真实产线 |

## 3. 角色视图

同一套数据，不同角色只看自己要做的那一个决定。

| 角色 | 看哪一屏 | 要做的决定 | 典型动作 |
| --- | --- | --- | --- |
| 班组长 | 总览 + 当班异常 | 是否停线待检 | 接收告警，组织首件复判 |
| 工艺工程师 | 工序 × 参数漂移 | 调整工艺窗口 / 加严抽检 | 确认因果链，提交工艺变更 |
| 设备工程师 | 设备 × 班次良率 | 是否停机保养 / 换件 | 按设备聚合的复判清单 |
| 质量经理 | 损失构成 + 质量门禁 | 是否放行 / 客户通报 | 批次追溯与放行决策 |
| 厂长 | 三线良率与目标缺口 | 资源与优先级 | 只看趋势与缺口，不看单点 |

## 4. 下一阶段优先级

1. **接真实 MES 导出**（见 [mes_schema.md](mes_schema.md)），用一条真实线跑通全链路；
2. 告警去重与合并（同一漂移的多个参数合并为一条事件）；
3. 建议采纳率回写，先积累 4 周人工反馈；
4. 在“有人确认”的前提下接入 LLM 做措辞与工单检索；
5. 最后才讨论 L3 的自动化工单，且必须保留人工闸门。
